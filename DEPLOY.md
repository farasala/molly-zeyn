## Три шага в дашбордах

Коннекторы этого не умеют: снятие защиты и переменные окружения на Vercel не входят в их API,
а настройки аутентификации Supabase — тем более.

**Проверено 5 сентября: шаг 1 сделан, шаги 2 и 3 — нет.**

### 1. Снять защиту с сайта (Vercel) — СДЕЛАНО

Vercel Authentication выключен, сайт больше не за логин-стеной Vercel.

### 2. Прописать переменные окружения (Vercel)

Vercel → **Settings** → **Environment Variables**. Добавить две, для всех окружений
(Production, Preview, Development):

```
NEXT_PUBLIC_SUPABASE_URL       = https://uwkosphzadpfonjvjanb.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY  = sb_publishable_3PB2N1WM8o17EYkD1aNybQ_UxjexNX_
```

Эти переменные вшиваются в сборку, поэтому после добавления нужен **Redeploy**:
Deployments → последний деплой → «···» → **Redeploy**.

Без них сайт соберётся, но каждая страница будет отдавать ошибку. Именно это сейчас
и происходит: `https://english-studio-molly-9f55.vercel.app` отвечает
`500 MIDDLEWARE_INVOCATION_FAILED` — middleware не находит адрес Supabase.

### 3. Выключить подтверждение почты (Supabase)

Supabase → проект **english-studio** → **Authentication** → **Sign In / Providers** →
**Email** → выключить **Confirm email** → **Save**.

Иначе после регистрации студент не попадёт внутрь, пока не откроет письмо, а встроенная почта
Supabase на бесплатном плане шлёт всего пару писем в час — целую группу так не завести.

Проверено: подтверждение всё ещё включено. Регистрация проходит, строка в `profiles` создаётся,
но сессии нет — форма показывает «Account created. Open the confirmation link in your email».

Заодно стоит включить **Leaked Password Protection** (Authentication → Policies) — Supabase
будет отбивать пароли из утечек. Бесплатно и уместно для школы.

## Что осталось на потом

### GitHub

Репозитория нет — GitHub-коннектор в этой сессии недоступен, а Vercel-коннектор не смог создать
git-проект (аккаунт без команды). Сейчас на Vercel лежит **снимок файлов**, а не связка
с репозиторием: каждое следующее изменение придётся заливать так же вручную.

Чтобы это починить, когда будет удобно:

1. Создать пустой приватный репозиторий `english-studio` на [github.com/new](https://github.com/new)
   — без README, .gitignore и лицензии.
2. Прислать мне адрес — я подключу remote и запушу всю историю.
3. Vercel → **Settings** → **Git** → **Connect Git Repository** → выбрать его.

После этого каждый `git push` в `main` пересобирает сайт сам.

### Домен

Купить на hoster.kz только домен (хостинг не нужен), затем Vercel → **Settings** → **Domains** →
добавить `example.kz` и `www.example.kz`. Vercel покажет DNS-записи — обычно
`A @ → 76.76.21.21` и `CNAME www → cname.vercel-dns.com`, но **сверяйтесь с тем, что показал
именно ваш Vercel**. Прописать их в панели hoster.kz, удалив парковочные записи хостера.
Обновление DNS — от 15 минут до нескольких часов, HTTPS Vercel выпустит сам.

Потом в Supabase → **Authentication** → **URL Configuration** вписать домен в **Site URL**.
